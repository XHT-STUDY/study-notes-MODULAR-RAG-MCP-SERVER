# Agent 算法 / LLM 应用工程求职材料（基于本仓库）

> 核对时间：2026-09-24。项目定位：面向公司流程与制度问答的个人项目，使用样例文档验证；暂无企业部署、生产用户、业务收入或线上性能数据。以下简历措辞只使用源码、开发记录和本次实际运行的测试能够支持的事实。项目日期请按真实开发时间填写。

## 一、可直接放进简历的项目经历

**企业流程制度智能问答系统（RAG + Agent）｜个人项目｜独立设计与开发｜[真实起止时间]**

**背景**：面向公司内部流程与制度问答场景，员工查询报销、请假、入职或审批规则时，需要从较长的制度文档中定位具体条款并核对答案来源；关键词不一致、版本更新和缺少引用会增加查找与核对成本。围绕这一场景，独立设计知识检索与 Agent 接入系统。

**目标**：打通“制度文档摄取—检索—回答与条款引用—Agent 工具调用—评测与追踪”全链路，使流程制度问题能够返回可追溯的文档依据，并重点处理召回不稳定、制度版本更新、工具调用失控和效果难验证的问题。

**过程**：

- 设计 PDF 摄取与增量更新链路，串联解析、切块、增强及双索引写入；借助文件哈希去重、版本回滚和跨存储删除，降低重复处理及旧索引残留风险。
- 实现向量与 BM25 双路召回、RRF 融合和可选重排；对单路召回或重排失败设置回退，保证有可用检索链路时查询仍可返回，并用阶段追踪定位异常。
- 封装检索、集合列表、文档摘要、Agent 查询 4 个 MCP 工具；加入工具白名单、迭代上限及引用校验，限制越权与失控循环。
- 修复标签缺失导致评测指标恒为 0 的问题；补齐源级 Hit Rate/MRR、chunk 级指标和 4 组消融，使不同检索策略可比较。
- 完成 Agent 循环、检索融合、重排回退与评测模块的专项回归；本次本机运行 113 个相关单测全部通过，覆盖工具调用、异常回退与指标计算等关键路径。

**结果**：交付可从 PDF 摄取到 MCP 调用的本地可运行系统，提供 **4 个 MCP 工具、3 种可配置 Agent 循环策略、4 组检索消融配置**；上述 **113/113 个专项测试通过**。曾在 **7 份样例 PDF、5 条查询**上完成探索性评测：`source_hit_rate=1.0`、`source_mrr=0.7667`；该样本集仅有一个目标来源，命中率容易饱和，不能解释为真实场景准确率或业务收益。

**关键词**：Python、RAG、BM25、Dense Retrieval、RRF、Rerank、MCP、Agent Tool Calling、评测与可观测性。

## 二、为什么做，亮点在哪里

**项目动机**：流程制度问答需要的不只是生成一句回答，还要找到对应规定，并在制度修订后避免引用旧版本。一段演示代码难处理文档重复导入、错误召回、索引更新、工具越权及模型输出缺少来源等问题。本项目以此为设计场景，把异常路径和文档生命周期纳入系统；现阶段仍是用样例文档验证的个人项目。

1. **从一次检索到可追溯系统**：摄取、查询和 Agent 均可留下阶段记录。面试时展示某条查询的双路召回、融合、重排及回退轨迹，比笼统说“有可观测性”更有说服力。
2. **同一知识能力供 CLI、仪表盘和 MCP 使用**：把检索暴露为标准工具，使 Agent 能调用既有知识库能力；关闭 Agent 时仍能直通检索。
3. **把数据生命周期纳入 RAG**：文件哈希去重、版本快照、同步删除和回滚，处理“旧版本仍被检索到”这类常见问题。
4. **真实的负结果也能证明技术判断**：现有 5 问小样本消融中，Sparse 的 `source_mrr=0.8667`，Hybrid 为 `0.7667`，Dense 为 `0.7333`。这表明当前样本与配置下，混合方案没有优于稀疏检索；应扩大样本并按问题类型调参，而不是宣称“混合检索提升 XX%”。
5. **Agent 的控制边界清晰**：工具白名单、循环上限、格式错误回喂、越界引用过滤和直通降级，比仅实现一个 ReAct 提示词更值得讲。

## 三、难点、问题与解决方式

| 遇到的问题 | 判断与处理 | 可展示的证据 |
| --- | --- | --- |
| 向量分数与 BM25 分数尺度不同，无法直接相加 | 用 RRF 对名次融合，再可选重排；单路失败时保留另一条链路 | `src/core/query_engine/hybrid_search.py`、`fusion.py`、回退单测 |
| 文档更新后多个索引可能不一致 | 文件哈希识别重复、版本记录及快照、跨 Chroma/BM25/图片/处理记录的协调删除与失败回滚 | `src/ingestion/pipeline.py`、`document_manager.py` |
| 早期评测标签为空，Hit Rate/MRR 恒为 0 | 补 `expected_sources`，采用跨机器可移植的来源级指标，保留 chunk 指标作辅助；加入 4 组消融 | `tests/fixtures/golden_test_set.json`、`DEVELOPMENT_LOG.md` Phase 3 |
| 不同 LLM Provider 缺少统一原生函数调用 | 在基类中增加统一的文本工具协议解析，将错误格式回喂模型；不改各 Provider 适配器 | `src/libs/llm/base_llm.py`、`src/core/agent/agent_runner.py` |
| Agent 可能递归调用自己、调用未授权工具或陷入循环 | 注册时排除 `agent_query`、调用前检查白名单、设置迭代上限；未启用时直接委托原检索工具 | `src/mcp_server/tools/agent_query.py`、Agent 单测 |

## 四、面试讲述模板

### 60–90 秒版本

“这是我独立做的个人项目，定位是回答公司流程和制度问题，例如员工查找报销或审批规则时，系统应能给出答案及文档依据。我用样例 PDF 验证从导入到 Agent 查询的完整链路：摄取侧做解析、切块、增量更新；查询侧做向量加 BM25 双路召回、RRF 融合、可选重排和失败回退；再通过 MCP 暴露四个工具。最费时间的是评测与一致性：原来评测标签为空，指标一直是 0；我补齐源级标注并做四组消融。小样本里 Sparse 的 MRR 反而高于 Hybrid，所以我把它作为下一轮调优的基线。目前有 113 个关键模块专项测试通过，但没有真实企业部署或业务收益数据。”

### 高频追问与回答抓手

1. **为什么要 BM25 + Dense + RRF？** 从精确术语与语义改写的互补性讲起，解释 RRF 为什么不需要分数归一化；接着主动说现有样本不支持“必然更优”，展示消融结果。
2. **你的 Agent 到底有什么自主性？** 说明工具选择、循环执行、检索结果不足时二次检索及三种策略的具体差别；同时说明它不是多 Agent 系统，也没有训练模型。
3. **工具调用错了怎么办？** 讲解析三态、错误回喂、白名单、排除自调用、最大迭代次数和直通降级；若面试官追问幂等性，区分只读检索工具与未来写操作工具。
4. **数据更新怎么避免旧答案？** 从文件身份、chunk ID、版本快照、协调删除与回滚讲完整路径，展示更新失败的测试用例。
5. **为什么 100% Source Hit 不能证明准确？** 只有 5 条问题且目标来源一致，指标容易饱和；需要不同来源、不可回答问题、改写/术语/跨文档分层集，并补充答案忠实度与人工判分。
6. **RAG 与 Agent 如何评测？** 分别定义来源命中、MRR、答案有据性、工具选择正确率、任务成功率、平均步骤数、P50/P95 时延与单任务 token 成本；说明当前项目只验证了其中一部分。

## 五、投递与准备策略

**岗位筛选**：优先投递 LLM 应用工程、RAG 工程、Agent 应用/平台工程、AI 后端。偏算法岗位可投“Agent 策略/评测/应用算法”方向；要求 SFT、DPO、PPO/GRPO、模型训练与论文成果的岗位，应先补实际训练实验。不要因为职位名都叫“Agent 算法”就用同一份简历。

**简历布局**：项目名、个人项目标识、背景/目标各一句；正文 4–5 条只写自己的决策、实现和证据，技术栈放末尾。可在项目链接旁提供 README、复现步骤、一次真实消融报告和 1–2 个失败案例。避免“企业级上线”“服务 2000+ 文档”“准确率 92%”“时延 800ms”“业务答疑下降 60%”等无数据支持的话；仓库旧 `RESUME.md` 中这些数据是占位包装，不应直接投递。

**补强顺序（建议两周）**：

1. 扩展黄金集到至少 50–100 条，以报销、请假、入职、审批等流程制度为题材，覆盖精确术语、同义改写、跨段、多文档、版本冲突与不可回答问题；逐条保存来源与参考答案，并隔离开发集/验证集。先使用公开或自编的脱敏样例，不暗示使用真实企业制度数据。
2. 固定同一硬件、索引、模型、Top-K 和数据集，测 Dense、Sparse、Hybrid、Hybrid+Rerank；记录 Hit Rate@K、MRR、P50/P95 延迟、token 成本及失败样例。只有跑出真实差异，才把“提升 X%”写入简历。
3. 为 Agent 增加任务级评测：工具调用正确率、任务成功率、平均步骤数、越权拒绝率、异常恢复率；对比直接检索与 Agent，判断复杂度是否有收益。
4. 做 2–3 个可演示的坏案例：旧索引残留、召回失败、工具越权或引用越界。每个案例保存“复现输入→原因→修复→回归结果”。
5. 准备基础面试：Python 异步/并发、索引与数据库、缓存和超时；RAG 的切块/召回/重排/评测；Agent 的工具调用/状态/记忆/安全；偏算法岗位再补 Transformer、SFT/DPO/RL 和论文复现。

**投递执行**：每个 JD 标注“工程落地、检索评测、Agent 编排、模型训练”四类要求，用同一真实项目材料调整 bullet 顺序；申请前核对岗位发布日期和学历/年限限制。面试后记录追问与答不出的证据，优先把缺口变成可复现实验，而不是继续堆概念。
