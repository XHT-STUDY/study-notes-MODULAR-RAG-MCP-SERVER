## 二、RAG(八股)· 面试题

### 5.3 切割 → 5.3.4 常见面试问题

1. 常见的分块策略有哪些?各自有什么优缺点?
2. 你的项目中是如何确定分块策略的?
3. RAG 的 Chunking 策略如何设计?遇到过哪些问题?如何调整?
4. 手写算法:按照句子边界进行文本分块,避免截断句子
5. 技术文档的相关内容跨越多个 Chunk,应该如何优化?什么时候需要扩充上下文?
6. 你的文档分块会使用滑动窗口吗?滑窗长度一般是多少?
7. 你的系统中有没有使用更高级的召回或分块方案?
8. Embedding 切 Chunk 应该怎么做?为什么固定长度切分经常不够?
9. 硬切分在实际场景中有哪些弊端?
10. 为什么内部文档需要设置 chunk_size=1000?1000 是不是太大了?

- 如果我做 RAG 召回的相关内容里,被人恶意注入了一些错误的信息,你觉得会影响大模型的生成内容吗?怎么避免?

### 9.4 场景题小测试(方案选型)

1. 我在做一个 coding agent,要在中小代码库里定位函数/改代码,用什么?
2. 代码库超大(比如 100GB、上千万文件),grep 扫盘太慢了怎么办?
3. 要查用户鉴权相关的代码,但关键词散在 auth / login / session / jwt 里,grep 搜不全,怎么办?
4. 要分析一份合同、或对比两份文档找出遗漏了什么,用 RAG 吗?
5. 要给公司几十万份客服/法律/Wiki 文档做问答系统,用什么?
6. 企业数据到了 TB / PB 级,长上下文完全装不下,怎么办?
7. 查询需要按作者过滤 + 按提交时间排序 + 按路径匹配这种带条件的检索,用什么?
8. 模型够强(Opus / GPT-5 级)、预算也够,想要最好的检索质量,怎么做?
